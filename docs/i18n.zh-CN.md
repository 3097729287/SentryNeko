# 国际化

[English](i18n.md) | **简体中文**

文案分两层存放。前端把全部界面文案放在 locale JSON 里，并根据错误 `code` 挑选文本；后端
只返回该 `code` 以及由 `services/i18n.rs` 本地化的兜底 `message`。两层互不复制对方的对照
表，注释里也不存放文案。

## 语言

| 标签 | 语言 | 状态 |
| --- | --- | --- |
| `en-US` | 英文 | 默认 |
| `zh-CN` | 简体中文 | 已支持 |
| `ja-JP` | 日文 | 预留，随 T30 到来 |

`services/i18n.rs` 目前暴露 `Language::{ZhCn, EnUs}`、`Language::DEFAULT`（`en-US`）以及
供设置页使用的 `Language::ALL`。

## 文案放在哪里

| 文案 | 归属 | 位置 | 任务 |
| --- | --- | --- | --- |
| 界面文案 | 前端 | `src/i18n/locales/<tag>.json` | T07 |
| 兜底文案 | 后端 | `services/i18n.rs` | T06 |
| 错误语义 | 契约 | `utils/response.rs` 的 `ApiCode`，由 `src/types/index.ts` 镜像 | T03 |
| 诊断信息 | 后端 | 失败处的 `details` | — |

## 前端

T07 按 `README.md` 中的目录结构落地 `src/i18n/`：i18next 与 react-i18next，每个语言标签一
个 JSON 文件放在 `src/i18n/locales/` 下，key 按功能分组（`todo.*`、`pomodoro.*`、
`settings.*`），漏翻从 key 本身就能看出来。`useI18n.ts` 负责运行时切换语言并持久化
（T16），`I18nProvider.tsx` 把 provider 接入 `App.tsx`。

在此之前约定已经生效：不得硬编码界面文案，且每条面向用户的文案都必须在同一个提交里同时
存在于两份 locale 文件中。

## 后端

命令返回错误码而不是翻译好的句子：前端按 `code` 分支，后端 `message` 只是给日志、以及给
前端尚未认识的错误码兜底（见 `docs/commands.md`）。`services/i18n.rs` 提供这份兜底：

- `Language::code()` / `Language::from_code()` 在枚举与 BCP-47 标签（`"zh-CN"`、
  `"en-US"`）之间转换，未知标签返回 `None`。
- `ApiCode::message_in(language)` 就是错误码 → 文案对照表；它的 `en-US` 分支委托给
  `utils/response.rs` 的 `ApiCode::default_message()`，英文文案只有一份。
- `ApiError::localized(language)` 只在文案仍是英文默认值时替换，带上下文的文案保持不变：

```rust
let generic = ApiError::new(ApiCode::Io).localized(Language::ZhCn);
assert_eq!(generic.message(), "输入输出错误");

let specific = ApiError::invalid_input("title must not be empty").localized(Language::ZhCn);
assert_eq!(specific.message(), "title must not be empty");
```

`details` 永不本地化：它是给日志与问题反馈用的诊断信息。

| 错误码 | `en-US` | `zh-CN` |
| --- | --- | --- |
| `OK` | OK | 成功 |
| `INVALID_INPUT` | Invalid input | 输入无效 |
| `NOT_FOUND` | Record not found | 记录不存在 |
| `CONFLICT` | Conflicting state | 状态冲突 |
| `DATABASE` | Database error | 数据库错误 |
| `IO` | I/O error | 输入输出错误 |
| `PERMISSION_DENIED` | Operation denied by the system | 系统拒绝了该操作 |
| `UNSUPPORTED` | Not supported yet | 暂不支持 |
| `INTERNAL` | Internal error | 内部错误 |

## 新增语言

1. 在 `services/i18n.rs` 的 `Language` 与 `Language::ALL` 中增加变体，并在 `code()` 与
   `from_code()` 中补上标签。
2. 为每个错误码补 `message_in` 分支——遍历 `Language::ALL` 与 `CODES` 的测试会在缺少文案
   时失败。
3. 新增 `src/i18n/locales/<tag>.json`（T07），并在设置页增加选项（T16）。
4. 在本文档上面的语言表中补一行。

## 约定

1. 新增面向用户的文案必须在同一个提交里同时写入两份 locale JSON（见 `CONTRIBUTING.md` 的
   完成标准）。
2. 新增错误码意味着：`ApiCode`、`src/types/index.ts` 中的 `ApiCode` 联合类型、
   `docs/commands.md` 错误码表中的一行、`message_in` 每种语言的分支，以及本文档上面的
   对照表。
3. 文案属于 locale 文件与上面的对照表，不放在代码注释里。
