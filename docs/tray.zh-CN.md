# 系统托盘

窗口是这个应用的脸面，而不是应用本身：前台追踪、番茄钟计时和闹钟在窗口隐藏后依然运行。通过托盘
或再次启动应用，都可以恢复已有窗口。

## 关闭不等于退出

`services/tray.rs::hide_on_close` 拦截主窗口的 `CloseRequested`，取消关闭并隐藏窗口。进程继续
存活，所以 `RunningCollector`、`RunningScheduler` 和前端的计时器都照常运行。托盘里的
`退出 SentryNeko` 是唯一的退出口：它调用 `app.exit(0)`，随后 `RunEvent::Exit` 停掉后台线程并
结束采集器那条未闭合的记录。

## 再次启动

`lib.rs` 在通知插件和应用 setup 之前注册官方 `tauri-plugin-single-instance`。后续启动会通知
已有实例，并在创建另一个窗口、托盘图标、数据库连接池、采集器或调度器之前退出。操作系统仍会为
这次启动短暂创建进程，随后只留下原来的常驻进程。

依赖固定到上游的 [Windows 启动竞态修复](https://github.com/tauri-apps/plugins-workspace/pull/3704)。
已发布的 2.5.4 在第二个进程看到首个进程的互斥量、但 IPC 窗口尚未创建时，可能继续执行 setup。
固定的修复会等待该窗口，并确保后续进程退出，包括转发超时的情况。

回调调用托盘菜单也在使用的 `services/tray.rs::show_window`，依次取消最小化、显示并聚焦已有
主窗口，包括开机自启后隐藏在托盘的窗口。这里始终显示窗口，不切换可见性，所以窗口已经可见时
再次启动也会保持显示。原有托盘图标和菜单继续工作。应用退出时插件释放实例锁，因此从托盘退出
后可以重新启动。

插件提供 Windows、macOS 和 Linux 后端；SentryNeko 本身仍然仅支持 README 中声明的 Windows。

### Windows 冒烟测试

1. 启动构建出的可执行文件，保持窗口可见并切换到另一个应用，再次启动。原窗口应获得焦点，
   只保留一个常驻应用进程和一个托盘图标。
2. 最小化窗口后再次启动。同一个窗口应恢复并获得焦点。
3. 关闭窗口到托盘后再次启动。同一个窗口应重新显示。重复多次，包括快速连续启动；不应留下
   额外的常驻进程或托盘图标。
4. 在这些尝试后使用托盘的显示/隐藏和开始番茄钟操作，确认两者仍然有效。
5. 从托盘退出，带 `--autostart` 启动并确认窗口保持隐藏，再正常启动以恢复窗口。再次退出并
   启动，确认实例锁已释放。

## 菜单

| 菜单项 | 行为 |
| --- | --- |
| 开始番茄钟 | 先显示窗口，再推送 `tray-start-pomodoro`；外壳重新加载时长并从 store 启动计时，所以这一轮和从页面上启动的完全一致 |
| `今日：…` | 一个禁用项，由 `tray-stats` 线程每分钟刷新：本地当天的专注秒数与完成任务数，走热力图聚合，所以两个数字遵循同一套日历规则 |
| 显示 / 隐藏窗口 | 切换可见性；左键单击图标等效 |
| 退出 SentryNeko | 结束进程 |

菜单在启动时按 `config.json` 里的语言构建一次。`set_language` 会就地重写它，所以在设置页切换
语言时，这份原生文案也跟着切换。

## 文案

菜单项和 `今日：…` 都在 `services/tray.rs` 里拼，与通知文案放在一起：原生文案由 Windows 绘制，
而不是 webview，所以归后端管。两种语言都有单元测试覆盖，包括今日行的两种形态——当天较短时用
分钟，超过一小时就带上小时。

## 开机自启

没有单独的进程需要安装：应用本身就是常驻进程，所以“开机自启”就是
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的一条值，由 `services/autostart.rs` 写入：

- 设置页有一个开关，调用 `set_autostart`；它写入“当前可执行文件的带引号路径 + `--autostart`”。
  同一条命令写两次仍只有一条值；关闭开关即删除（本来没有也不算失败）。
- 指向别处的旧值——旧的安装目录、被移动过的文件夹——会被读成“关闭”，于是重新打开开关是修复它，
  而不是留着一条过期命令。
- `--autostart` 就是“开机启动不弹窗”的原因：setup 阶段看到这个参数就隐藏窗口，应用直接等在托盘里。
- 注册表访问藏在 `RunKey` 这个 trait 后面，所以判断逻辑用假实现做单测；Win32 调用和其余平台代码
  一起放在 `utils/windows.rs`。

## 限制

- 托盘在实践中是 Windows 专有的：图标取自打包图标，应用本身也是 Windows 构建。找不到图标时
  启动会在 setup 阶段报错，而不是悄悄少一个托盘。
- `今日：…` 每分钟才对一次账，而不是每次变化都更新：原生菜单在用户查看时无法改写，而对一句
  摘要来说一分钟足够短。
- 自启项指向的是“做这次修改的那个可执行文件”，在 `pnpm tauri dev` 下就是 `target/debug` 里的
  调试构建；从开发运行里打开这个开关，注册的就是调试构建。
- `T28`（全局快捷键）基于这个托盘，目前尚未实现。
